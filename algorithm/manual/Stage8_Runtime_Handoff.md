Stage 8 не требует сети. Владелец выполняет три ручных шага: ратификация состава, передача модулей рантайма
и передача секретов. Агент эти действия не выполняет (AR-201, AR-204, AR-804).

## 1. Ратификация состава (`S8-OPEN-1`)

1. Открыть `runtime/manifests/RuntimeManifest.json`.
2. Подтвердить или изменить список `directories` (добавить/убрать каталоги, поправить назначение).
3. Перевести `status` в `RATIFIED`, дату — в `statusNote`.
4. Прогнать `pwsh -File ./runtime/bootstrap/Assert-RuntimeState.ps1` — проверка `A2.3` должна стать PASS.

## 2. Передача модулей рантайма (`S8-OPEN-2`)

| Шаг | Действие | Контроль |
|---|---|---|
| 1 | Скопировать модули с носителя `F:` в `C:\Vitality\bin\` | Источник и назначение фиксируются в отчёте |
| 2 | Посчитать SHA256 каждого файла | `Get-FileHash -Algorithm SHA256` |
| 3 | Внести хэши в `packages/hashes/PACKAGES_SHA256.txt` | Строки вида `<SHA256>  F:\...` → `C:\Vitality\bin\<файл>` |
| 4 | Проверить запуск модуля вручную | Первый запуск делает владелец, не скрипт |

Правило: бинарники в Git не коммитятся (AR-804); при обновлении модуля — новая строка хэша, старая помечается датой.

## 3. Передача секретов

1. Секреты — отдельными файлами в `C:\Vitality\config\` (например `db_password.txt`), по одному значению на файл.
2. Права на `config\`: владелец и SYSTEM; Administrators — только чтение (`-ApplyAcl`).
3. Секреты не попадают в манифест, скрипты, отчёты и Git (`STRUC_009`, `NC_HARDCODED_SECRETS`).
4. Резервная копия секретов — вне станции (менеджер паролей владельца); `C:\Vitality\backup\` — только локальный слепок.

## 4. Задачи и службы рантайма (`S8-OPEN-3`)

Если рантайму нужны задачи планировщика или службы, они **не создаются автоматически**: владелец оформляет
их как декларацию в домене `tweaks/tasks` или отдельным решением (ADR) с верификацией. Агент ничего не
регистрирует сам (AR-204).

## 5. Приёмка этапа

1. `pwsh -File ./scripts/Stage8_Runtime_Deploy.ps1 -Audit` — предусловия без FAIL.
2. `pwsh -File ./runtime/bootstrap/Deploy-Runtime.ps1` (при необходимости `-ApplyAcl`).
3. `pwsh -File ./runtime/bootstrap/Assert-RuntimeState.ps1` → `docs/artifacts/Stage8_runtime.md` без FAIL.
4. Заполнить §4 ручного контроля в `docs/artifacts/Stage8_Report.md`, перевести отчёт в DONE.
5. `pwsh -File ./scripts/Final_Acceptance.ps1` — сводная приёмка (`F8`).

## 6. Ограничения

- Сеть не требуется и не поднимается (AR-709).
- Удаление чего-либо в `C:\Vitality\` — только вручную владельцем (AR-201).
- Изменение состава — только через манифест (AR-501, ADR-0017).

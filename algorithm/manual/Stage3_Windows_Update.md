## Цель

Довести ядро Windows 11 IoT Enterprise LTSC 24H2 до актуального состояния (накопительные пакеты, обновления безопасности, обновления подсистемы гипервизора) **внутри Audit Mode**, не допустив при этом дрейфа драйверов и вендорского ПО ASUS. По завершении — немедленно вернуть систему в полную сетевую изоляцию.

Это **единственный** момент алгоритма, когда хост открывается во внешний мир до цементирования контура (README §4.5). Окно доступа должно быть минимальным.

## Предусловия

| # | Требование |
|---|---|
| 1 | Система находится на рабочем столе встроенного Администратора в Audit Mode (Stage 2) |
| 2 | Окно Sysprep закрыто (крестик/«Отмена»), обобщение НЕ запускалось |
| 3 | Файл ответов Stage 2 отработал: проверки `A2`–`A5` из `algorithm/auto/Stage2_Audit_Mode_Workflow.md` пройдены |
| 4 | Резервная копия точки восстановления не требуется (система чистая), но фиксируется текущее значение сборки (`UBR`) |

## Шаги

### Шаг 0. Фиксация исходной сборки

Открыть PowerShell (от Администратора) и записать в отчёт:

```powershell
$v = Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion'
[pscustomobject]@{
    ProductName = $v.ProductName
    DisplayVersion = $v.DisplayVersion
    CurrentBuild = $v.CurrentBuild
    UBR = $v.UBR
    EditionID = $v.EditionID
    InstallDate = ([datetime]'1970-01-01').AddSeconds($v.InstallDate).ToLocalTime()
} | Format-List

# Контроль состояния Audit Mode (должно быть 1)
(Get-ItemProperty 'HKLM:\SYSTEM\Setup').CmdLine
(Get-ItemProperty 'HKLM:\SYSTEM\Setup').SystemSetupInProgress
```

Значения `CurrentBuild`/`UBR` — эталон «до»; после наката они обязаны вырасти.

### Шаг 1. Подготовка интерфейса Центра обновления

1. Подключить сетевой кабель или активировать Wi-Fi (окно сети — только на время этапа).
2. `Win + I` → **Центр обновления Windows**.
3. **Критически важно:** переключатель «Получайте последние обновления, как только они будут доступны» → **Отключено**. Это блокирует доставку экспериментальных и необязательных пакетов и лишний фоновый I/O.
4. Открыть блок **«Необязательные обновления»** → **«Обновления драйверов»** и убедиться, что в очередь не встают пакеты ASUS/Realtek. Обязательные обновления драйверов себе не присваивать (ADR-0007: драйверы ставятся «голыми» INF на Stage 4).

### Шаг 2. Циклический накат

1. Нажать «Проверить наличие обновлений».
2. Проверить состав списка. Ожидается:
   - накопительное обновление Windows 11 версии 24H2;
   - обновление безопасности .NET Framework;
   - Security Intelligence Update для Microsoft Defender.
3. Если в общем потоке появились пакеты с «ASUSTeK Computer Inc.», «ASUS», «Extension» — **не исключать установку принудительно**: контур нейтрализации отработает на Stage 4 (`PAT-15`, «Временный щит PnP») и Stage 6 (`PAT-11`). Если пакет попал именно в блок «Необязательные обновления» — не выбирать его.
4. «Скачать и обновить» → дождаться завершения.
5. Перезагрузка возвращает систему в Audit Mode (менеджер загрузки удерживает состояние по кусту `HKLM\SYSTEM\Setup`) — окно Sysprep появится снова; **закрыть его**.
6. Повторять шаги 1–5, пока Центр обновления не сообщит: «У вас установлены все актуальные обновления».
7. Дополнительно: после последнего цикла нажать «Проверить наличие обновлений» ещё раз через 5–10 минут и убедиться, что счётчик снова нулевой (защита от «двухволновой» выдачи).

### Шаг 3. Фиксация результата

Повторить команды Шага 0 и записать в отчёт новые `CurrentBuild`/`UBR`.

Дополнительно зафиксировать:

```powershell
# Список установленных обновлений (последние 30)
Get-CimInstance Win32_QuickFixEngineering |
    Sort-Object InstalledOn -Descending | Select-Object -First 30 HotFixID, Description, InstalledOn |
    Format-Table -AutoSize

# Размер WinSxS до сжатия (Stage 4 выполнит ResetBase)
(Get-ChildItem 'C:\Windows\WinSxS' -Recurse -Force -ErrorAction SilentlyContinue |
    Measure-Object -Property Length -Sum).Sum / 1GB
```

### Шаг 4. Мгновенный разрыв сетевого линка

1. **Извлечь сетевой кабель** / перевести Wi-Fi в режим «В самолёте».
2. Проверить изоляцию:

```powershell
Get-NetAdapter | Select-Object Name, Status, LinkSpeed
Test-NetConnection -ComputerName 8.8.8.8 -InformationLevel Quiet   # ожидается: False / ошибка
```

3. Переходить к Stage 4 разрешено только при подтверждённой изоляции.

## Критерии выхода

| # | Критерий |
|---|---|
| 1 | Центр обновления сообщает «У вас установлены все актуальные обновления» (в двух последовательных циклах) |
| 2 | Значения `CurrentBuild`/`UBR` выросли относительно исходных и зафиксированы в отчёте |
| 3 | Окно Sysprep закрывалось после каждой перезагрузки, обобщение не запускалось |
| 4 | Необязательные обновления и пакеты драйверов ASUS **не** устанавливались |
| 5 | Сеть физически изолирована, проверка `Test-NetConnection` подтверждает отсутствие связи |
| 6 | Заполнен `docs/artifacts/Stage3_Report.md` |

## Ограничения и риски

| ID | Риск | Митигация |
|---|---|---|
| `R1` | WU подтянет драйверы ASUS/OEM (драйверный дрейф) | `SearchOrderConfig=0` (Stage 2), ручной контроль списка, отказ от необязательных обновлений; последствия устраняются на Stage 4 |
| `R2` | `TrustedInstaller` перезапишет IFEO-заглушки при установке кумулятивного пакета | Ожидаемо и допустимо: повторная пропись и цементирование — Stage 4 (`Audit_Final_Clean.ps1`) и Stage 6 (`PAT-11`). Проверка `A2`/`A3` переносится на Stage 4 |
| `R3` | Перезагрузка уйдёт в OOBE вместо Audit Mode | Удерживается флагом `HKLM\SYSTEM\Setup`; проверка на Шаге 0; при потере состояния — `sysprep /audit` вручную |
| `R4` | Прерывание наката на середине цикла (сбой питания) | Не обновлять без питания от сети; при сбое — перезапуск цикла: CBS устойчив к прерываниям |
| `R5` | Сеть осталась включённой после этапа | Явная проверка изоляции (Шаг 4.2) входит в критерии выхода |
| `R6` | Автоматизация обновлений сторонними утилитами (PSWindowsUpdate и др.) | Не применяется на этом шаге: ручной GUI-контроль сохраняет возможность визуального отсева. Изменение подхода — только через ADR (AR-710, `GATE_TOOL_REPLACE`) |

Ранбук описывает **порядок физического прогона** всех этапов на целевой машине (ASUS Vivobook, i5-12400F,
16 ГБ, NVMe 480 ГБ) и формы фиксации результатов. Прогон выполняет владелец: агент мутаций не производит
(AR-204), сеть не поднимает (AR-709).

## 3. Формы фиксации

### 3.1 Журнал прогона

| Дата | Этап | Команда/действие | Результат (код/статус) | Отчёт | Отклонения |
|---|---|---|---|---|---|
| | | | | | |

### 3.2 Карточка этапа (заполняется на каждый этап)

```
Этап:            <N>
Дата/время:      <…>
Версия репо:     <git rev-parse --short HEAD>
Сеть:            <off | окно открыто/закрыто, кем, когда>
Выполнено:       <команды по порядку>
Результат:       <PASS | FAIL | WARN + коды возврата>
Отчёты:          <docs/artifacts/…>
Отклонения:      <что не совпало с ожиданием>
Решения:          <что предпринято, ссылки на GATE-запросы>
```

### 3.3 Правила фиксации

- Один этап — один атомарный коммит по итогам прогона (AR-805); отчёты этапов обновляются в том же коммите.
- Заполненные формы попадают в `docs/artifacts/Stage<N>_Report.md` (раздел ручного контроля), а не в чат.
- `backups/`, `logs/`, временные файлы в Git не коммитятся (AR-804, STRUC_008).

## 4. Правила при FAIL

1. **Стоп.** Не продолжать к следующему этапу, пока FAIL не разобран (AR-302).
2. Зафиксировать: код возврата, отчёт, последние строки журнала (`logs/<script-id>_*.log`).
3. Откат — по `docs/artifacts/Recovery_Procedure.md` (раздел соответствующего объекта).
4. Если ситуация не описана контрактом (несколько равнозначных вариантов) — `GATE_AMBIGUITY`: остановиться
   и запросить решение по формату §4.2 README; ничего не «додумывать» (AR-906).
5. Разрушительные варианты (`bcdedit /import`, `wsl --unregister`, форматирование) — только с явного
   одобрения владельца (AR-202).

## 5. Критерии завершения прогона

- `Stage*_Report.md` этапов 1–8 переведены в `DONE`, разделы ручного контроля заполнены.
- `Final_Acceptance.md` без FAIL (проверки `F0.*`, `F1`–`F8`).
- Все окна сети закрыты; `Stage6_immunity.md` подтверждён после этапов 7–8.
- Метрики §3.5 обновлены в `Final_Report.md`; отклонения и waiver'ы перечислены явно.

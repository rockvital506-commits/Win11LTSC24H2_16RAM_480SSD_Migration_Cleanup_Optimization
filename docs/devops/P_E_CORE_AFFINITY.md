## 1. Метод определения P-ядер

| Уровень | Механизм | Роль |
|---|---|---|
| Основной | `GetLogicalProcessorInformationEx(RelationProcessorCore)` → поле `EfficiencyClass` | Классы ядер: больший класс — производительные (P) |
| Перекрёстный | Sysinternals `coreinfo -c` (офлайн) | Контроль количества логических процессоров |
| Санитарный | `Win32_Processor` | Общее число ядер/потоков; тип ядер не различает |
| Запрещён | Хардкод маски | AR-704 |

Признак гибридности: `EfficiencyClass` принимает более одного значения. Если значение одно — скрипт **не применяет**
привязку: `Hybrid=$false`, WARN, решение за владельцем (AR-906).

## 2. Политика

| Нагрузка | Ядра | Приоритет | Инструмент |
|---|---|---|---|
| `vmmemWSL` (WSL2) | P | ≤ `Normal` | `Set-WorkloadAffinity.ps1` |
| Компиляция/сборка (`msbuild`, `cl`, `devenv`) | P | ≤ `Normal` | там же (запуск по мере процессов) |
| `vmware-vmx` | P | ≤ `Normal` | там же |
| Фоновые задачи (индексация, обслуживание) | E | `BelowNormal` | Штатный планировщик Windows |

Предусловие: VBS/HVCI/LSA отключены (ADR-0012) — при включённых механизмах политика не применяется (AR-706).

## 3. Схема питания

`devops/cpu-policy/power-plan.json` объявляет целевые значения (`PROCTHROTTLEMIN=100`, `PROCTHROTTLEMAX=100`,
`CPMINCORES=100` для AC). Применение — только `-ApplyPowerPlan`; по умолчанию значения **сверяются** (WARN при
расхождении), потому что схема питания — предпочтение владельца, а не требование контура.

## 4. Верификация

| ID | Проверка | Критерий |
|---|---|---|
| `A0.1` | Определение классов ядер | `Hybrid=$true`, маска выведена, метод зафиксирован |
| `A1.1` | Привязка процессов | целевые процессы на маске P-ядер, приоритет ≤ `Normal` |
| `A2.*` | Схема питания | значения совпадают с декларацией (иначе WARN) |
| — | (вручную) сборка проекта | время сборки не ухудшилось против прогона без привязки |

## 5. Откат

| Действие | Команда |
|---|---|
| Снять привязку с процесса | `(Get-Process -Name vmmemWSL).ProcessorAffinity = <все ядра>` или перезапуск процесса |
| Вернуть схему питания | `powercfg /setactive <прежняя схема>` (имя прежней схемы фиксируется в отчёте) |

## 2. Требования к выравниванию (basis: PAT-NEW-6)

| Вариант выравнивания | Гранулярность | Оценка для NVMe |
|---|---|---|
| Нет (устаревшее) | 512 Б | НЕ применять: read-modify-write, ускоренный износ |
| 4 КБ | 4096 Б | минимум для SSD |
| **1 MiB** | 1 048 576 Б | **принято**: кратно и 512 Б, и 4096 Б (LBA), совпадает с рекомендованной Windows 11 GPT-геометрией |

Арифметика: 1 MiB = 2048 секторов × 512 Б = 256 секторов × 4096 Б. Выравнивание сохраняется независимо от того, какой LBA-режим репортит накопитель (512e или 4Kn), и совпадает с границами, которые использует `setup.exe` при автоматической разметке.

## 3. Схема разделов (утверждено ADR-0007)

| # | Тип | ФС | Размер | Байты (эталон) | Кластер | Точка монтирования | Назначение |
|---|---|---|---|---|---|---|---|
| 1 | EFI System Partition (ESP) | FAT32 | 260 MiB | 272 629 760 | 4 КБ | **скрытая, без буквы** (ADR-0011) | загрузчик Windows, BCD |
| 2 | MSR | — | 16 MiB | 16 777 216 | — | hidden | Microsoft System Reserved |
| 3 | Windows | NTFS | 200 GiB | 214 748 364 800 | 4 КБ | `C:\` | ОС, `Program Files`, `Users` |
| 4 | Data | NTFS | **весь остаток ≈246.7 GiB** | по факту | 64 КБ | `D:\` | ВМ, контейнеры, проекты, бэкапы |

**Единицы измерения (ADR-0011):** размеры выражены в MiB/GiB (двоичные, 1024-based). Накопитель «480 ГБ» ≈ 447.03 GiB полезной ёмкости. Баланс: 200 GiB (C:) + 260 MiB (ESP) + 16 MiB (MSR) + ≈246.7 GiB (D:, остаток) ≈ 447.03 GiB; остаток отдан разделу Data, нераспределённого пространства нет. Служебные структуры GPT (33 сектора ≈ 16.9 КБ) и выравнивание учтены в остатке.

## 4. Обоснование размеров

### 4.1 ESP 260 MiB

- Минимум FAT32 для загрузочных файлов — 100 MiB; Microsoft рекомендует 260 MiB с прицелом на будущие накопительные обновления и накопление записей BCD/WinRE.
- Ограничение FAT32 в 4 GiB на файл несущественно: файлы загрузчика измеряются единицами мегабайт.
- `docs/research/anchor1.md` упоминал 100–250 (МБ); **утверждено 260 MiB** (README §6.3.2, ADR-0007) — расхождение снято (DEV-3, закрыт).
- **Буква диска не назначается** (ADR-0011): `F:` закреплена за USB-носителем Ventoy; вариант `C:\EFI` (README §7.2 до rev.2) отклонён. При необходимости доступ — временно через `mountvol` по процедуре восстановления.

### 4.2 MSR 16 МБ

- Фиксированный документированный размер Microsoft; не форматируется и не содержит пользовательских данных.
- Служебная область для операций конвертации/обслуживания GPT.

### 4.3 C: 200 GiB (кластер 4 КБ)

- Windows LTSC IoT после Stage 3 — ~25 ГБ; `Program Files` — ~5 ГБ; профили — ~10 ГБ; WinSxS после `/ResetBase` — ~5 ГБ; фиксированный pagefile 4 ГБ; temp/cache — ~3 ГБ; резерв ~150 ГБ под обновления и приложения.
- Кластер 4 КБ — компромисс для системного раздела с большим количеством мелких файлов (реестр, шрифты, кэши).

### 4.4 D: весь остаток ≈246.7 GiB (кластер 64 КБ)

- Размер намеренно не фиксирован: раздел создаётся последним и забирает всю оставшуюся ёмкость — это исключает нераспределённое пространство и делает схему устойчивой к разбросу фактической ёмкости накопителей класса «480 ГБ» (447–448 GiB).
- Крупные последовательные файлы: диски ВМ (`.vmdk`), тома контейнеров, артефакты сборок, снапшоты конфигураций.
- 64 КБ снижает число метаданных-операций и фрагментацию при последовательной записи; побочный эффект — увеличенный расход места на мелких файлах и несовместимость с NTFS-сжатием/дедупликацией в полном объёме. Для целевого профиля (ВМ/контейнеры) выгода перевешивает.
- exFAT для раздела с dev-данными **запрещён** (`NC_EXFAT_DATA`): нет POSIX-атрибутов, симлинков и сокетов — ломает `git clone` и компиляторы.

### 4.5 Единицы измерения и эталонные значения (ADR-0011)

| Параметр | В интерфейсе разметки | Байты (эталон) |
|---|---|---|
| ESP | 260 MiB | 272 629 760 |
| MSR | 16 MiB | 16 777 216 |
| C: | 200 GiB | 214 748 364 800 |
| D: | весь остаток (≈246.7 GiB) | вычисляется инструментом |

Правило: **числа вводить в тех же единицах, что отображает инструмент** (MiB/GiB), а при сомнении сверяться с байтовым эталоном. Историческая формулировка «200 ГБ + 279.7 ГБ» (SI) выведена из употребления: она сходилась с ёмкостью 480 ГБ только в десятичной системе и приводила к расхождению на десятки GiB при вводе в GiB-поле (DEV-2).

## 5. Операции разметки (DiskGenius, вручную)

Полный порядок — `algorithm/auto/Stage1_DiskGenius_Partition.md`. Кратко:

1. Забэкапить старую таблицу разделов и, при необходимости, пользовательские данные (до разметки: `BACKUP OLD SYSTEM` — §4.5 README).
2. Инициализировать диск как GPT.
3. Создать ESP 260 MiB (FAT32, 4 КБ кластер) с выравниванием 1 MiB; букву диска **не назначать**.
4. Создать MSR 16 МБ.
5. Создать раздел Windows **200 GiB** (NTFS, 4 КБ кластер, 1 MiB) — в поле размера вводить двоичные единицы.
6. Создать раздел Data — **весь остаток** (NTFS, 64 КБ кластер, 1 MiB).
7. Забэкапить новую таблицу разделов на `F:\BACKUPS\`.
8. Выполнить верификацию (`Stage1_DiskGenius_Partition.ps1`).

Решение о **ручной** разметке (вместо секции `DiskConfiguration` в unattend) зафиксировано ADR-0007: инженер контролирует границы разделов и выравнивание, а не доверяет эвристике установщика.

## 6. Пост-настройка NTFS (после установки ОС)

```powershell
# D:\ — отключение генерации коротких имён 8.3 (снижает объём метаданных при массовом создании файлов)
fsutil behavior set disable8dot3 D: 1

# Отключение обновления времени последнего доступа (снижает записи при чтении)
fsutil behavior set disablelastaccess 1

# Запрет шифрования файла подкачки (согласовано с фиксированным pagefile, Stage 4)
fsutil behavior set encryptpagingfile 0
```

Проверка — `Stage1_DiskGenius_Partition.ps1 -Audit` (раздел «fsutil»). Изменения pagefile/hiberfil выполняются на Stage 4 (`PAT-13`, `PAT-14`), здесь фиксируются только NTFS-параметры тома.

## 7. Открытые пункты и риски

| ID | Пункт | Действие |
|---|---|---|
| `OPEN-1` | Точка монтирования ESP: README §6.2 указывал `F:\EFI`, §7.2 — `C:\EFI` | **RESOLVED** (ADR-0011): ESP скрытая, без буквы диска |
| `OPEN-2` | Intel VMD/RST | В BIOS проверить состояние VMD: при включённом режиме `setup.exe` может не видеть NVMe. Варианты: отключить VMD либо интегрировать IRST-драйвер — решение до разметки, зафиксировать в отчёте |
| `OPEN-3` | Secure Boot | Зафиксировать фактическое состояние прошивки в отчёте; влияние на `DISABLE-LSA-ISOLATION/DISABLE-VBS` проверяется инструментально на Stage 4 (`H-001`) |
| `OPEN-4` | Точная модель ASUS Vivobook | Внести в отчёт Stage 1 для трассируемости драйверов |
| `RISK-1` | Изменение разметки после Stage 1 невозможно без потери данных | `GATE_PARTITIONING`; бэкап до разметки обязателен |
| `DEV-2` | Единицы измерения (SI против GiB) для размеров разделов | **RESOLVED** (ADR-0011): MiB/GiB, байтовые эталоны в §4.5 |

## 8. Верификация

| Проверка | Инструмент | Критерий |
|---|---|---|
| GPT, 4 раздела | `Get-Disk`, `Get-Partition` | partition style = GPT, тип разделов совпадает |
| Выравнивание | `(Get-Partition).Offset % 1MB` | 0 для всех разделов |
| ESP/MSR размеры | `Get-Partition` | 260 MiB (272 629 760 Б) / 16 MiB (16 777 216 Б) ± допуск |
| C: размер | `Get-Partition` | 200 GiB (214 748 364 800 Б) ±512 MiB |
| D: размер | `Get-Partition` | остаток ≈246.7 GiB ±4096 MiB |
| ESP без буквы | `Get-Partition` | `DriveLetter = $null` |
| ФС и кластеры | `Get-Volume`, `fsutil` | FAT32 4 КБ; NTFS 4 КБ; NTFS 64 КБ |
| fsutil-параметры | `fsutil behavior query` | `disable8dot3 D:` = 1, `disablelastaccess` = 1 |
| Резервная копия таблицы | файл на `F:\BACKUPS\` | существует, SHA256 в отчёте |

Все проверки автоматизированы в `scripts/Stage1_DiskGenius_Partition.ps1` (read-only, PAT-NEW-7).

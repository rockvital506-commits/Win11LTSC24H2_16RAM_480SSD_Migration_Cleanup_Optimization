## 0. Назначение и порядок применения

1. Документ фиксирует обязательные правила разработки, исполнения и сопровождения автоматизации проекта.
2. Правила действуют наравне с README (Section 1–5). При расхождении приоритет — по §4.4 README (Immutable Core → Verified Patterns → ADR → документация этапа → инструкции пользователя → предположения агента).
3. **Степени обязательности:**
   - `[MUST]` / `[MUST NOT]` — блокирующие. Нарушение = провал верификации, коммит запрещён.
   - `[SHOULD]` — рекомендуемое; отклонение допускается только с письменным обоснованием в отчёте этапа или ADR.
   - `[MAY]` — допустимая практика.
4. **Принцип «правило = исполняемый артефакт»:** каждое правило либо принуждается машинно (`.editorconfig`, `.gitattributes`, валидатор, Pester), либо является gate-процедурой с явным протоколом.

### 0.1 Карта принуждения

| Механизм | Файл | Покрывает правила |
|---|---|---|
| Редакторный конфиг | `.editorconfig` | AR-101, AR-102, AR-103, AR-104, AR-406 (отступы) |

| Gate-процедуры (ручные) | §4.2 README | AR-201…AR-207, AR-504, AR-801…AR-806, AR-905, AR-906 |

### 0.2 Протокол изменения правил

1. Изменение, добавление или отмена правила — **только** через ADR (`docs/decisions/`) + явное одобрение владельца.
2. Каждое изменение фиксируется в `docs/rules/RULES_CHANGELOG.md` с указанием: версия, дата, ID правил, причина, ссылка на ADR.
3. **Временное исключение (waiver):** оформляется ADR с обязательными полями «причина», «область действия», «дата истечения». Просроченный waiver автоматически недействителен.
4. Валидатор и `.editorconfig` обновляются в том же коммите, что и правило (иначе правило не исполняется).

## AR-1xx — Кодировки и окончания строк

**Ключевая коллизия (утверждена):** PowerShell требует UTF-8 **с** BOM, а файлы ответов WinPE/`setup.exe` и батники — **без** BOM. Единое правило «BOM везде» технически неверно, поэтому норма задаётся **по классу файла**.

### AR-1.1 Матрица кодировок (AR-101)

| Класс файла | Кодировка | EOL | Обоснование |
|---|---|---|---|
| `.ps1`, `.psm1`, `.psd1` | UTF-8 **с BOM** | CRLF | Windows PowerShell 5.1 без BOM читает файл как ANSI/CP1251 → кириллица и ошибки парсинга |
| `.xml` (unattend, u_w11_ltsc_iot, ventoy-шаблоны) | UTF-8 **без BOM** | CRLF | WinPE `setup.exe` отклоняет файл ответов с BOM |
| `.bat`, `.cmd` | UTF-8 без BOM, **контент только ASCII** | CRLF | `cmd.exe` не понимает BOM; кириллица ломает парсинг |
| `.vbs` | **ASCII-only** | CRLF | WSH не поддерживает UTF-8 |
| `.reg` | UTF-16LE с BOM | CRLF | Формат `Windows Registry Editor Version 5.00` |
| `.inf` | **ASCII-only** | CRLF | Установщик драйверов не переносит Unicode/BOM |
| `.json`, `.yaml`, `.yml` | UTF-8 без BOM | LF | Машинные форматы; strict JSON запрещает BOM |
| `.md`, `.gitignore`, `.gitattributes`, `.editorconfig` | UTF-8 без BOM | LF | Нативные парсеры и удобные диффы |
| `.wslconfig`, `.vmx`, `hosts`, `*.conf` | ASCII (UTF-8 без BOM, ASCII-контент) | CRLF | Гипервизор и Linux-парсеры — только plain ASCII |
| `.csv`, `.txt` для Excel | UTF-8 **с BOM** | CRLF | Иначе Excel портит кириллицу |

### AR-1.2 Правила

| ID | Степень | Правило | Принуждение |
|---|---|---|---|
| `AR-101` | `[MUST]` | Соблюдать матрицу кодировок по классу файла (AR-1.1) | `.editorconfig` + валидатор |
| `AR-102` | `[MUST]` | Все текстовые файлы — **CRLF**, кроме `.md/.json/.yaml/.yml/.gitignore/.gitattributes/.editorconfig` (**LF**) | `.gitattributes` |
| `AR-103` | `[MUST]` | Файл всегда заканчивается переводом строки; mixed-EOL запрещён | валидатор |
| `AR-104` | `[MUST]` | Сохранение только в редакторах, уважающих `.editorconfig` (VS Code / Notepad++); «Сохранить как ANSI» запрещено | валидатор + ревью |
| `AR-105` | `[MUST]` | Русский текст в `.bat/.cmd/.vbs/.inf/.vmx` запрещён; при необходимости — обёртка `.ps1` | валидатор (эвристика) |
| `AR-106` | `[MUST]` | Перед коммитом валидатор `Test-RepositoryConventions.ps1` должен вернуть `PASS` | валидатор |

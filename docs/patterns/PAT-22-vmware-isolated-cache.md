## Контекст

VMware по умолчанию создаёт рядом с `.vmx` файл `*.vmem` (выгрузка памяти гостя) и включает page-sharing между ВМ.
На системе с одним SSD это означает: (а) лишние многогигабайтные записи (износ, `SC_SSD_LONGEVITY`),
(б) непредсказуемое поведение при нехватке ОЗУ, (в) следы работы гостя на диске.

## Решение

Единый набор директив для каждой ВМ (шаблон `VM.vmx.template`), применяемый идемпотентно:

| Директива | Значение | Назначение |
|---|---|---|
| `priority.grabbed` | `"high"` | Приоритет процессов активной ВМ |
| `priority.ungrabbed` | `"normal"` | Приоритет в фоне |
| `sched.mem.pshare.enable` | `"FALSE"` | Запрет page-sharing между ВМ (снижение нагрузки, предсказуемость) |
| `mainMem.useNamedFile` | `"FALSE"` | Память не выгружается в `*.vmem` |
| `mainMem.backing` | `"swap"` | Резерв — страницы хоста, а не файл |
| `vhv.enable` | `"TRUE"` | Вложенная виртуализация (Docker внутри гостя) |

## Реализация

| Артефакт | Путь |
|---|---|
| Шаблон | `devops/hypervisor/vmware/VM.vmx.template` |
| Апплейер | `devops/hypervisor/Configure-WhpCoexistence.ps1` (`-VmRoot D:\VM`) |
| Резерв копий | `backups/<UTC>_stage7-vmx/<имя ВМ>.vmx` (AR-304) |

## Проверка

| ID | Критерий |
|---|---|
| `C1.<vm>.vmx` | все ключи шаблона присутствуют в файле |
| — | повторный прогон не вносит изменений (AR-303) |
| — | (вручную) после запуска ВМ файл `*.vmem` не создаётся |

## Замечания

- Директивы применяются ко всем `*.vmx` под `D:\VM`; ВМ, созданные позже, подхватываются повторным прогоном.
- `mainMem.backing = "swap"` — документированная опция; при включённом host-cache поведение проверяется `P7.3`.
- Ключи специфичны для VMware Workstation; для сторонних гипервизоров шаблон не применяется (ADR-0002, вариант D отклонён).

## Контекст

Твики этапов 3–4 (обновления, драйверы, реестр, службы, AppX, память, NTFS) должны попасть в шаблон `Default User`, а не в профиль конкретного пользователя. Windows для этого предоставляет Audit Mode: сессия встроенного Администратора до прохождения OOBE, в которой установка считается нераспакованной, а профиль-источник ещё не «занят» пользователем.

Пока система в Audit Mode, каждая перезагрузка возвращает окно Sysprep — это не сбой, а признак сохранённого режима.

## Решение

| Фаза | Этап | Действие | Артефакт |
|---|---|---|---|
| Вход | 2 | После первой перезагрузки установки: `<Mode>Audit</Mode>` (вариант A, отключён до проверки в ВМ) или `Ctrl+Shift+F3` на экране OOBE (вариант B, документированный) | `templates/u_w11_ltsc_iot.xml.template`, `S2-OPEN-2` |
| Подтверждение | 2 | Проверка `HKLM\SYSTEM\Setup\SystemSetupInProgress = 1` | `Stage2_Report.md` |
| Работа | 3–4 | Обновления, драйверы, твики, санитария — без сети (AR-709) | `Stage3_Report.md`, `Stage4_Report.md` |
| Контроль | 3–5 | После каждой перезагрузки окно Sysprep закрывается **Cancel** (не «OK» и не «Generalize») | `R3` в Stage-отчётах |
| Выход | 5 | `sysprep.exe /oobe /generalize /shutdown /unattend:C:\Windows\System32\Sysprep\unattend.xml` | `PAT-16` (файл № 2), `ADR-0014` |

## Реализация

```powershell
# Признак сохранённого Audit Mode (проверяет Stage 5, P0.1)
(Get-ItemProperty 'HKLM:\SYSTEM\Setup' -Name SystemSetupInProgress).SystemSetupInProgress   # ожидание: 1
```

Окно Sysprep после перезагрузки — ожидаемое поведение. Единственная безопасная кнопка — `Cancel`; `OK` запускает выход из режима без подготовки, `Generalize` — необратимое запечатывание.

## Верификация

| ID | Проверка | Критерий |
|---|---|---|
| `A1` | Вход в Audit Mode состоялся | профиль `Administrator` активен, OOBE не завершён |
| `A2` | Флаг режима | `SystemSetupInProgress = 1` (P0.1 в `Stage5_Sysprep_Prepare.ps1`) |
| `A3` | Режим пережил перезагрузки этапов 3–4 | окно Sysprep появлялось после каждой перезагрузки |
| `A4` | Выход выполнен штатно | `sysprep_succeeded.tag`; при следующем старте — OOBE |
| `A5` | Твики перенесены | новый пользователь `devops` наследует настройки Default User (`H-003`) |

## Ограничения и риски

- Случайное нажатие `OK`/`Generalize` в окне Sysprep — потеря режима или преждевременное запечатывание (`R3` в `Stage3_Report.md`).
- Установка обновлений Windows может вернуть систему к обычному профилю (риск `R3`); контроль — флаг `SystemSetupInProgress` после каждого цикла.
- Встроенный Администратор не должен получать MSA/доменную учётную запись: `CopyProfile` работает только для локального профиля.
- Часть современных настроек не переносится через `CopyProfile` (ADR-0014 п.2) — компенсация политиками Stage 6.

## Альтернативы

| Вариант | Причина отклонения |
|---|---|
| Настройка после OOBE от имени `devops` | Твики не попадут в `Default User`; `SC_FACTORY_RESET_CAPABLE` не достигается |
| `<Mode>Audit</Mode>` как единственный вход | Поддержка схемой не подтверждена до теста в ВМ (`S2-OPEN-2`); `Ctrl+Shift+F3` документирован и бесплатен |
| Вход через `auditSystem`/`auditUser` RunSynchronous | Требует файла ответов на носителе и не даёт выигрыша |

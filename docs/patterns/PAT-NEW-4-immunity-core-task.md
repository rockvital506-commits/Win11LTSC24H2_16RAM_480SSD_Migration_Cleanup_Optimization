## Контекст

Контур должен восстанавливаться не только при загрузке, но и при каждой разблокировке: снятие ACL-замков возможно администратором (это осознанная возможность отката), а также в ранних сценариях обслуживания. Нужен повторяемый запуск без интерактивного входа.

## Решение

Задача планировщика `System_Immunity_Core`, **декларируемая манифестом** (`tweaks/tasks/TaskManifest.json`):

| Поле | Значение | Обоснование |
|---|---|---|
| Триггеры | `BootTrigger` + `SessionStateChangeTrigger` (`SessionUnlock`) | покрытие загрузки и разблокировки любой сессии |
| Принципал | `SYSTEM (S-1-5-18)`, RunLevel Highest | независимость от активной сессии; SYSTEM имеет доступ к защищаемым объектам в фазе grant |
| Действие | `wscript.exe D:\GD_Tool\Launcher.vbs` | скрытый запуск, PAT-NEW-3 |
| Настройки | игнорировать повторные запуски (`IgnoreNew`), без требований к питанию | не создавать очередей при быстрых циклах вход-выход |

Регистрация — только из XML, собранного по манифесту (`Register-ScheduledTask -Force`), что даёт идемпотентность и отсутствие ручных GUI-шагов.

## Проверка

| ID | Критерий |
|---|---|
| `TASK-001.1` | задача существует, `State = Ready` |
| `TASK-001.2` | принципал `SYSTEM`, RunLevel Highest, триггеры boot + unlock |
| `TASK-001.3` | (вручную) «Выполнить» в планировщике → транзакция в журнале, код 0 |
| `TR101…TR106` | задачи-реаниматоры отключены (Disable) |

## Замечания

- Вывод реаниматоров из строя обратимо (Disable + экспорт XML в бэкап); удаление — только явным флагом `-Unregister` (AR-204).
- Вариант с интерактивным пользователем отвергнут ADR-0015: контур не должен зависеть от токена администратора.

## Контекст

На NVMe SSD операции чтения/записи выполняются страницами и блоками стирания NAND. Если начало раздела не совпадает с границей физического блока, драйвер выполняет read-modify-write для каждой логической записи: растёт объём записи на NAND (WAF), падает скорость, сокращается ресурс накопителя. Дополнительно несовпадение границ разделов с ожиданиями Windows создаёт лишние операции при работе с GPT.

## Решение

Все разделы NVMe выравниваются по границе **1 MiB (1 048 576 байт)**.

Обоснование арифметикой:

| Гранулярность | Значение | Комментарий |
|---|---|---|
| Сектор 512 Б | 1 MiB = 2048 секторов | целое |
| Сектор 4 КБ (4Kn/512e) | 1 MiB = 256 секторов | целое |
| Типичный блок стирания NAND | 1–4 MiB | старт раздела не попадает в середину блока для большинства носителей |
| Дефолт Windows 11 GPT | 1 MiB | совпадение с ожиданиями `setup.exe` и служб обслуживания |

## Реализация

| Этап | Действие |
|---|---|
| Разметка | DiskGenius: при создании каждого раздела явно задаётся выравнивание `1 MiB` (не «по умолчанию») |
| Проверка | `Stage1_DiskGenius_Partition.ps1`: `(Get-Partition -DiskNumber N).Offset % 1MB` = 0 |
| Бэкап | после разметки — резервная копия таблицы разделов на `F:\BACKUPS\` |
| Документирование | схема и допуски — `docs/storage/*` (`PAT-NEW-7`) |

## Верификация

```powershell
# Все разделы диска 0 должны удовлетворять условию Offset % 1 MiB == 0
Get-Partition -DiskNumber 0 | Select-Object PartitionNumber, Offset, Size, @{n='Aligned';e={ ($_.Offset % 1MB) -eq 0 }}
```

Ожидаемый результат: `Aligned = True` для всех разделов (включая ESP и MSR). Допуск — 0 байт.

## Ограничения и риски

- Настройка выполняется **один раз**; изменение после установки ОС невозможно без потери данных (`GATE_PARTITIONING`).
- «Автоматическое» выравнивание по 4 КБ (например, устаревшими утилитами) считается нарушением паттерна, даже если диск работает.
- Выравнивание не компенсирует отсутствие TRIM и не заменяет меры SC_SSD_LONGEVITY (фиксированный pagefile, удаление hiberfil.sys — Stage 4).

## Альтернативы

| Вариант | Причина отклонения |
|---|---|
| Без выравнивания (512 Б) | read-modify-write, ускоренный износ, падение производительности |
| 4 КБ | Минимум, но не совпадает с блоками стирания и дефолтами Windows |
| 8 MiB | Избыточный расход, выигрыш не подтверждён для потребительских NVMe |

## Context

Накопитель — NVMe SSD 480 ГБ, целевой профиль — DevOps-станция (WSL2 + Docker + VMware). Оба фактора создают постоянный поток записи. Дополнительно:

- `hiberfil.sys` при 16 ГБ ОЗУ занимает значительный объём и перезаписывается при каждом уходе в сон;
- динамический файл подкачки фрагментируется и расширяется при пиковых нагрузках (сборки, контейнеры), что даёт лавинообразный рост WAF (write amplification factor);
- обновления Windows накапливают резервные копии компонентов в WinSxS, увеличивая объём и количество операций обслуживания.

Критерий проекта `SC_SSD_LONGEVITY` фиксирует: `hiberfil.sys` удалён, `pagefile` фиксирован, `SearchIndex` отключён.

## Decision

1. **Гибернация полностью отключается** (`powercfg /hibernate off`) — `PAT-14`. Файл `hiberfil.sys` удаляется операционной системой; режим сна остаётся доступен, режим гибернации — нет.
2. **Файл подкачки фиксируется монолитно:** `AutomaticManagedPagefile = False`, `InitialSize = MaximumSize = 4096 МБ` (`PAT-13`). Значение определено для 16 ГБ ОЗУ и профиля по умолчанию; параметризовано (`-PageFileMb`), изменение — через обновление этого ADR.
3. **Индексация поиска отключается** (служба `WSearch`, `tweaks/services/ServiceGate.json`): постоянный фоновый I/O не оправдан для станции с известной структурой каталогов.
4. **Хранилище компонентов сжимается** (`dism /online /cleanup-image /StartComponentCleanup /ResetBase`, `PAT-18`) и кэш `SoftwareDistribution\Download` очищается. `ResetBase` необратим — это принятое следствие (см. Consequences).
5. **Проверка состояния обязательна:** `Assert-TweakState.ps1` контролирует `hiberfil.sys` (отсутствие), настройки подкачки и тип запуска `WSearch`.
6. **Изменение значений без ADR запрещено:** `pagefile` влияет на стабильность (возможны отказы при нехватке памяти), `hibernation` — на сценарии восстановления после сбоя питания.

## Consequences

**Положительные:**

- Снижение объёма записи на NAND: меньше фрагментации, ниже WAF, выше предсказуемость износа.
- Освобождение места: `hiberfil.sys` (до 12–16 ГБ), резервные копии компонентов после `ResetBase`, кэш обновлений.
- Ядро не тратит циклы на сжатие/расширение/перемещение файла подкачки — меньше DPC-латентность (согласуется с ADR-0012).

**Отрицательные / компромиссы:**

- **Нет гибернации:** при полном разряде батареи данные из ОЗУ теряются. Компенсация: рабочие артефакты — в Git, состояния — в манифестах; для ВМ предусмотрены снапшоты.
- **Фиксированная подкачка 4096 МБ:** при экстремальных пиках (много параллельных контейнеров + сборка) возможны ошибки выделения памяти. Компенсация: лимиты WSL2 (`PAT-21`, 6 ГБ из 16) и параметр `-PageFileMb` для повышения до 8192 при подтверждённой необходимости.
- **`ResetBase` необратим:** накопительные обновления нельзя удалить. Повторное развёртывание выполняется через Sysprep/Factory Reset, а не через откат обновлений (SC_FACTORY_RESET_CAPABLE).
- Отключение `WSearch` делает поиск в Проводнике/меню «Пуск» менее полным.

**Нейтральные:**

- Требуется перезагрузка для применения части изменений (подкачка), `ResetBase` — длительная операция.

## Alternatives

| Вариант | Причина отклонения |
|---|---|
| Оставить гибернацию | Прямое нарушение `SC_SSD_LONGEVITY`; скрытый износ и значительный объём |
| Динамический файл подкачки | Фрагментация и рост WAF при пиковых нагрузках контейнеров |
| Подкачка 8192 МБ по умолчанию | Избыточно для 16 ГБ ОЗУ при ограниченных лимитах WSL2; доступно параметром при необходимости |
| Перенос подкачки на `D:\` | Усложняет схему; выигрыш по износу отсутствует (тот же физический носитель) |
| Не выполнять `ResetBase` | Остаются резервные копии компонентов, Windows сохраняет возможность «реанимации» отключённых служб (см. `docs/research/step3.md`) |

| Поле | Значение |
|---|---|
| `ADR_ID` | ADR-0007 |
| `TITLE` | Partition scheme: 1 MiB alignment, manual DiskGenius, four partitions |
| `STATUS` | **ACCEPTED (rev.2 от 2026-10-01)** — размеры и точка монтирования ESP изменены ADR-0011 |
| `DATE` | 2026-10-01 |
| `AUTHOR` | AI-агент (Arena.ai) |
| `APPROVED_BY` | rockvital506-commits (контур утверждён как якорь1; схема зафиксирована в README §6.2/§7.2) |
| `SCHEMA_VERSION` | 3.0.0 |
| `RELATED` | `PAT-NEW-6`, `PAT-NEW-7`, `ADR-0011` (ревизия), `docs/storage/partitioning_research.md`, `C_drive_schema.md`, `D_drive_schema.md`, README §1.4 `SC_OPTIMAL_PARTITIONING`, §4.5, §6, §7 |

> **Ревизия rev.2 (2026-10-01, ADR-0011).** Текст решения ниже сохранён без изменений (ADR неизменяем). Актуальные значения: единицы измерения — MiB/GiB (а не «МБ/ГБ» без указания системы); ESP — 260 MiB, **без буквы диска** (вместо `C:\EFI`/`F:\EFI`); `C:` — 200 GiB (214 748 364 800 Б); `D:` — весь остаток ≈246.7 GiB. Критерий `V4` верификации читать в редакции ADR-0011 (W1–W6). Неизменно: GPT, UEFI, выравнивание 1 MiB, состав и порядок разделов, ФС и кластеры, ручная разметка, запрет exFAT.

---

## Context

Разметка NVMe SSD 480 ГБ выполняется один раз и до установки ОС: после Stage 1 изменение геометрии невозможно без потери данных (README §4.5, `GATE_PARTITIONING`). Требовалось зафиксировать:

1. таблицу разделов и режим загрузки;
2. гранулярность выравнивания;
3. размеры и файловые системы разделов;
4. способ выполнения разметки (ручной или автоматический);
5. способ повторяемой проверки схемы (SC_FACTORY_RESET_CAPABLE, PAT-NEW-7).

Исходные ограничения: целевая платформа — ASUS Vivobook (i7 6P+8E, 16 ГБ ОЗУ, NVMe 480 ГБ); целевой профиль — ВМ (VMware), контейнеры (Docker/WSL2), сборки C++ и `git`-репозитории; требование SC_SSD_LONGEVITY (минимизация паразитных записей).

В `docs/research/anchor1.md` упоминался ESP 100–250 МБ; README §6.3.2 и §7.2 фиксируют 260 МБ. Расхождение разрешается данным ADR в пользу 260 МБ.

## Decision

1. **Таблица разделов — GPT, режим загрузки — UEFI.** Legacy MBR не рассматривается: NVMe + UEFI, GPT обязательна для корректной работы WinRE и обновлений.
2. **Выравнивание всех разделов — 1 MiB** (`PAT-NEW-6`): кратно 512 Б и 4096 Б (LBA), совпадает с границами, используемыми `setup.exe`. Гипотеза `H-005` — VALIDATED.
3. **Схема разделов:**

| # | Тип | ФС | Размер | Кластер | Монтирование | Назначение |
|---|---|---|---|---|---|---|
| 1 | ESP | FAT32 | 260 МБ | 4 КБ | `C:\EFI` (см. OPEN-1) | загрузчик, BCD |
| 2 | MSR | — | 16 МБ | — | hidden | System Reserved |
| 3 | Windows | NTFS | 200 ГБ | 4 КБ | `C:\` | ОС, программы, профили |
| 4 | Data | NTFS | ~279 ГБ | 64 КБ | `D:\` | ВМ, контейнеры, проекты, бэкапы |

4. **Разметка выполняется вручную в DiskGenius** из WinPE. Секция `DiskConfiguration` в unattend **не используется**: инженер контролирует границы разделов и выравнивание, установщик не получает права изменять геометрию.
5. **exFAT для раздела данных запрещён** (`NC_EXFAT_DATA`): отсутствие POSIX-атрибутов, симлинков и сокетов.
6. **Обязательные артефакты Stage 1:** резервная копия старой таблицы разделов (до) и новой (после), `partitioning_research.md`, `C_drive_schema.md`, `D_drive_schema.md`, отчёт `Stage1_Report.md`, ADR-0007.
7. **Повторяемая проверка** — `scripts/Stage1_DiskGenius_Partition.ps1` (read-only, `PAT-NEW-7`): типы разделов, размеры, ФС, кластеры, выравнивание, NTFS-параметры.
8. **Открытые пункты фиксируются, а не «додумываются»:** точка монтирования ESP (`OPEN-1`), состояние Intel VMD/RST (`OPEN-2`), состояние Secure Boot (`OPEN-3`) — требуют решения/протоколирования до выполнения разметки.

## Consequences

**Положительные:**

- Выравнивание 1 MiB исключает read-modify-write на уровне NAND и продлевает ресурс SSD.
- Разделение `C:`/`D:` изолирует нагрузку ВМ и контейнеров от системного раздела, упрощает бэкап конфигураций и сохраняет ёмкость `C:`.
- Схема воспроизводима: подтверждается скриптом и бэкапом таблицы разделов (SC_FACTORY_RESET_CAPABLE).

**Отрицательные / компромиссы:**

- Кластер 64 КБ на `D:\` увеличивает расход места на мелких файлах и ограничивает сжатие/дедупликацию.
- Ручная разметка требует дисциплины инженера; ошибка необратима (страхуется бэкапом до разметки).
- ESP 260 МБ (а не 100 МБ) расходует дополнительно ~160 МБ — принято осознанно.

**Нейтральные:**

- `F:` остаётся за USB-носителем Ventoy, что и порождает открытый пункт `OPEN-1` по ESP.

## Alternatives

| Вариант | Описание | Причина отклонения |
|---|---|---|
| A | Секция `DiskConfiguration` в unattend (автоматическая разметка) | Инженер теряет контроль над границами и выравниванием; риск несовпадения с PAT-NEW-6; ADR-0005 фиксирует двухэтапный unattend без разметки |
| B | Разметка скриптом `diskpart`/PowerShell | Деструктивная автоматизация до появления защиты контура; нарушает принцип «ручной контроль необратимой операции» (AR-204) |
| C | Дефолтная разметка Windows Setup | `setup.exe` создаёт дополнительные разделы восстановления, размеры и выравнивание не контролируются |
| D | Один раздел `C:\` без `D:\` | Смешивание ВМ/контейнеров с системой: износ `C:`, усложнение бэкапов, риск потери рабочего окружения при переустановке ОС |
| E | exFAT для `D:\` | Запрещено `NC_EXFAT_DATA`: ломает `git clone` и компиляцию |

## Verification

| ID | Проверка | Инструмент | Критерий |
|---|---|---|---|
| `V1` | GPT + UEFI | `Get-Disk` | PartitionStyle = GPT, IsBoot = True |
| `V2` | 4 раздела правильных типов | `Get-Partition` | EFI / MSR / Basic / Basic |
| `V3` | Выравнивание 1 MiB | `Get-Partition` | `Offset % 1MB = 0` для всех |
| `V4` | Размеры | `Get-Partition` | 260 MiB / 16 MiB / 200 GiB / ≈246.7 GiB — редакция ADR-0011 (W1–W6) |
| `V5` | ФС и кластеры | `Get-Volume` | FAT32 4 КБ; NTFS 4 КБ; NTFS 64 КБ |
| `V6` | NTFS-параметры | `fsutil behavior query` | `disable8dot3 D:` = 1, `disablelastaccess` = 1 |
| `V7` | Бэкапы таблиц разделов | файлы `F:\BACKUPS\` | существуют + SHA256 в отчёте |

Автоматизация: `pwsh -File ./scripts/Stage1_DiskGenius_Partition.ps1 -ExportReport ./docs/artifacts/Stage1_partition_verify.md`.
Результат фиксируется в `docs/artifacts/Stage1_Report.md`; расхождение — стоп и запрос (`GATE_PARTITIONING`), а не «исправление на глаз».

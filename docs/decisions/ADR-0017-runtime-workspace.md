| Поле | Значение |
|---|---|
| `ADR_ID` | ADR-0017 |
| `STATUS` | ACCEPTED (Stage 8) |
| `DATE` | 2026-10-01 |
| `AUTHOR` | AI-агент (Arena.ai) |
| `RELATED` | README §1.3 (`WORKSPACE_ROOT`), §3.2, §5.1, §7.4, §9.8; AR-206, AR-301, AR-509, AR-804, STRUC_009; `NC_HARDCODED_SECRETS`; `docs/artifacts/Recovery_Procedure.md` |

## Контекст

README §1.3 фиксирует `WORKSPACE_ROOT = C:\Vitality\` (runtime) и `D:\GD_Tool\` (инструменты). До Stage 8
каталог существует как объявленная, но не описанная точка: состав, права и порядок развёртывания нигде не
закреплены, а `docs/storage/C_drive_schema.md` помечал его «runtime, после Stage 8» без деталей.

Stage 8 — последний этап: он разворачивает рабочую среду исполнения поверх уже иммунизированной станции
(Stage 6) и поднятого DevOps-контура (Stage 7), не меняя ни того, ни другого.

## Решение

1. **Структура репозитория.** Создаётся домен `runtime/` (манифесты и скрипты) и документация
   `docs/runtime/`. Основание — `GATE_STRUCTURE` (изменение корневой топологии); владелец одобрил
   Вариант A 2026-10-01 (запрос в формате §4.2, обновление Section 5 — часть этого ADR).
2. **Декларативность.** Состав каталога описан единственным источником — `runtime/manifests/RuntimeManifest.json`.
   Скрипт ничего не создаёт «по памяти»: набор директорий, правила и проверки читаются из манифеста (AR-501).
3. **Идемпотентность и маркер.** Развёртывание создаёт `C:\Vitality\.vitality.json` с версией схемы,
   временем UTC и SHA256 манифеста. Повторный запуск с тем же хэшем не меняет ничего (AR-301) и фиксируется
   как `PASS` без операций.
4. **Права доступа — без Deny.** Модель ACL: владелец-пользователь (создатель) и `NT AUTHORITY\SYSTEM` —
   `FullControl`, `BUILTIN\Administrators` — `ReadAndExecute`; наследование сохраняется. Запреты (Deny SYSTEM)
   в этом домене **не применяются**: они принадлежат контуру защиты Stage 6 (`ADR-0003`, PAT-11) и не должны
   расширяться на рабочие каталоги, иначе оператор теряет возможность их обслуживать.
   Права применяются только по явному флагу `-ApplyAcl` (AR-204, AR-506).
5. **Размещение данных.** `C:\Vitality\` — только код, конфигурация и состояние; крупные данные
   (образы, БД, кэши сборок, тома контейнеров, диски ВМ) остаются на `D:` — `SC_SSD_LONGEVITY`,
   `AR-509`, README §7.5.
6. **Секреты — только файлами.** Конфигурация с секретами живёт в `config\` как отдельные файлы вне Git
   (`STRUC_009`, `NC_HARDCODED_SECRETS`). Секретов в манифесте, скриптах и отчётах нет.
7. **Бинарники — не в Git.** Исполняемые модули рантайма поставляются офлайн с носителя `F:`; их SHA256
   фиксируются в `packages/hashes/PACKAGES_SHA256.txt` при передаче (AR-804, PAT-20).
8. **Состав — предложение до ратификации.** Перечень каталогов в манифесте имеет статус `PROPOSED`
   (`S8-OPEN-1`): владелец подтверждает или правит его. До ратификации развёртывание допустимо
   только в режиме `-Audit`; правки вносятся в один файл — манифест.
9. **Верификация — отдельный артефакт.** `Assert-RuntimeState.ps1` (только чтение) проверяет состав,
   маркер, дрейф и права; результат — `docs/artifacts/Stage8_runtime.md`; агрегируется финальной
   приёмкой (`Final_Acceptance.ps1`, проверка `F8`).

### 1.1 Разграничение с `tools/runtime/`

`tools/runtime/` (Stage 6, `ADR-0015`) — артефакты контура самозащиты, доставляемые в `D:\GD_Tool` на станции.
Новый домен `runtime/` отвечает за рабочую среду `C:\Vitality\`: манифест состава и скрипты развёртывания.
Разные целевые каталоги, разные владельцы решений; пересечений нет.

## Альтернативы

| Вариант | Оценка |
|---|---|
| A. Домен `runtime/` + `docs/runtime/` | **Принят.** Симметрия с `tweaks/`, `packages/`, `devops/`; один владелец манифеста; понятная граница ответственности |
| B. Разместить в `scripts/runtime/` и `docs/devops/` | Отклонён: домен растворяется в чужом, `docs/devops/` отвечает за WSL2/Docker/VMware, а не за рабочую среду; переразложение позже дороже |
| C. Описывать состав в самом скрипте | Отклонён: нарушает декларативность (AR-501/503) и усложняет правки владельцем |
| D. Хранить рантайм в репозитории и копировать при входе | Отклонён: репозиторий — источник, а не развёрнутая среда; копирование на каждом входе — лишние операции записи (AR-206, §1.5) |

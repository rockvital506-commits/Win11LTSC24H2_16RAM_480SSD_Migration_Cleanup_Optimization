## Context

Stage 6 собирает контур самозащиты на уже запечатанном хосте. Спецификация (`docs/research/step5.md`, `anchor1.md`) задаёт состав: слепок локальных политик через LGPO, запрещающие правила брандмауэра, NTFS-замки и задача `System_Immunity_Core`. Черновик содержит четыре инженерные проблемы:

1. **Порядок.** Если ACL-операция выполняется до внесения исключений Defender, поведенческий анализатор квалифицирует массовое изменение прав на системные каталоги как ransomware и блокирует процесс.
2. **Транзакция.** Жёсткий `deny` на запись для SYSTEM мешает последующему импорту политик (SYSTEM — исполнитель LGPO), поэтому нужна схема «снять замок → применить → поставить замок».
3. **Автономность рантайма.** Задача срабатывает при каждой разблокировке и при запуске системы, когда офлайн-носитель `F:` может быть отключён. Рантайм обязан работать без репозитория.
4. **Управляемость.** Черновик предполагает ручную регистрацию задачи в GUI и ручные же ACL-команды; при этом AR-501 требует деклараций, AR-304 — бэкапов, AR-307 — верификации, AR-204 — явного подтверждения для деструктивных действий.

## Decision

1. **Порядок фаз фиксирован:** (а) доверенная зона Defender → (б) развёртывание рантайма → (в) задача контура и вывод реаниматоров → (г) окно активации → (д) цементирование ACL → (е) верификация. Нарушение порядка запрещено.
2. **Доверенная зона объявлена и минимальна** (`tweaks/apply/Invoke-DefenderAllowList.ps1`): `D:\GD_Tool`, каталог `GroupPolicy`, файл `hosts`, компонент активации (`DEF-004`) и процесс `wscript.exe` (`DEF-005`). Расширение — только через новый ADR. Осознанно принято ослабление эвристик Defender на объявленном множестве: станция офлайн, установка ПО — только через `packages/` (Stage 7).
3. **Рантайм самодостаточен и отделён от репозитория:** `templates/ImmunityCore.ps1.template` рендерится в `D:\GD_Tool\ImmunityCore.ps1`; `AutoSetup.bat` — тонкий ASCII-оркестратор (AR-105), `Launcher.vbs` — скрытый запуск. Тяжёлая логика (grant/deny, LGPO, брандмауэр, проверки) — в PowerShell-ядре, а не в пакетных конструкциях.
4. **Транзакция идемпотентна:** grant → импорт → firewall → `gpupdate /force` → deny → верификация; каждое состояние проверяется до изменения (AR-303), результат пишется в `D:\GD_Tool\logs\ImmunityCore.log`.
5. **Задача контура — декларативна** (`tweaks/tasks/TaskManifest.json`): триггеры «при запуске» и «при разблокировании», принципал `SYSTEM (S-1-5-18)` вместо интерактивного пользователя — контур не зависит от активной сессии и срабатывает при разблокировке любым пользователем. Регистрация — из XML, собранного по манифесту (никакого ручного GUI-конфигурирования).
6. **Реаниматоры выводятся из строя обратимо:** по умолчанию `Disable` (XML каждой задачи экспортируется в бэкап, AR-304); `Unregister` — только явным флагом (AR-204). DENY на файл задачи (`denyWriteToSystem`) — опция, применяемая вместе с замками.
7. **Сеть остаётся под ручным управлением** (AR-709): ни один скрипт Stage 6 не поднимает и не опускает интерфейс; окно активации открывает и закрывает владелец по чек-листу `algorithm/manual/Stage6_Ohook_Activation.md`.
8. **Верификация — отдельный артефакт** (`tweaks/apply/Assert-ImmunityState.ps1`): замки, задача, реаниматоры, правила брандмауэра, DoH, доверенная зона, артефакты рантайма, слепок политик, статус активации и сквозной контроль твиков Stage 4.

## Consequences

**Положительные:**

- Контур воспроизводим: развёртывание, задачи и замки описаны декларациями и проверяются кодом возврата (AR-306).
- Рантайм переживает отключение `F:` и повторяется при каждой разблокировке — дрейф конфигурации исключён по построению.
- Обратимость: `Unregister`-операции не автоматизируются, ACL снимаются `Phase=Grant`, исключения Defender — `-Remove`.

**Отрицательные / компромиссы:**

- Ослабление Defender на объявленных путях и процессе (принято; компенсируется офлайн-профилем и контролем пакетов на Stage 7).
- Дублирование логики ACL: декларативный апплейер в репозитории и автономное ядро в `D:\GD_Tool`. Синхронность обеспечивается единым источником значений (манифесты) и проверкой `Assert-ImmunityState.ps1`; расхождение ловится проверками `GACL-*`.
- Задача от SYSTEM с правом записи в `D:\GD_Tool`: компромисс ради независимости от сессии.

**Нейтральные:**

- `-Unregister` и `-Remove` требуют явного запуска; первый прогон может занять несколько минут (LGPO + `gpupdate /force`).

## Alternatives

| Вариант | Причина отклонения |
|---|---|
| Ручная настройка по черновику (GUI-задача, ручные icacls) | Не воспроизводимо, нет бэкапов и верификации (AR-304, AR-307) |
| Рантайм, зависящий от репозитория на `F:` | Задача срабатывает при каждой разблокировке; носитель может быть отключён |
| Интерактивный пользователь с наивысшими правами | Контур не срабатывает, если сессия не активна; зависимость от токена администратора |
| «Тихая» задача без логов | Потеря наблюдаемости и возможности доказать применение |
| Автоматическое включение сети скриптом | Нарушение AR-709 и §4.5 (единственное окно доступа контролируется вручную) |

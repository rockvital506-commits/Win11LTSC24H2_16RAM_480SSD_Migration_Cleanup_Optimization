## Context

На этапе Stage 0 (Repository Initialization) требовалось определить структуру каталогов под три функциональных домена проекта:

1. твики ядра ОС Windows и реестра;
2. автоматизация установки пакетов (winget);
3. DevOps-окружение (WSL2 / Hyper-V / VMware с учётом архитектуры P+E-ядер).

Утверждённая ранее топология §5.1 README (`algorithm/`, `docs/`, `scripts/`, `templates/`, `tools/`) таких доменов не предусматривала, а смешение предметной логики в плоском `scripts/` привело бы к монолитным скриптам и неуправляемому дрейфу конфигурации.

Дополнительно: каталог `research1/` (файлы `anchor1`, `step1` … `step5`) физически существовал в репозитории, но не был описан в §5.1 — формальное нарушение `STRUC_002` и `NC_OUTSIDE_TOPOLOGY`.

В соответствии с §4.1 промптом `GATE_STRUCTURE` был поднят запрос с тремя вариантами (A: сохранить каркас + добавить домены; B: полная перестройка в домен-ориентированный монорепо; C: не трогать корень вообще).

## Decision

Владельцем утверждён **Вариант A**, дополненный переносом исследовательских материалов:

1. Корневой каркас §5.1 сохраняется: `algorithm/`, `docs/`, `scripts/`, `templates/`, `tools/`.
2. Добавляются три доменных каталога: `tweaks/`, `packages/`, `devops/`.
3. Добавляется каталог `tests/` (Pester + fixtures).
4. В `docs/` добавляются подкаталоги: `rules/`, `research/`, `core-tweaks/`, `packages/`, `devops/`.
5. Вводится двухслойная модель: **`scripts/Stage*.ps1`** — оркестрация (что запускает инженер на этапе N); **`tweaks/|packages/|devops/`** — доменные модули и декларативные манифесты (чем и по каким данным).
6. Каталог `research1/` переносится в `docs/research/` с добавлением расширения `.md`:
   `anchor1 → docs/research/anchor1.md`, `step1 → docs/research/step1.md`, …, `step5 → docs/research/step5.md`.
   Перенос выполняется как rename с сохранением истории Git; содержимое сохраняется байт-в-байт.
7. Section 5 README обновляется: §5.1 (дерево), §5.4 (дерево решений), §5.6 (маппинг Stage→артефакт с учётом доменов); §5.2/§5.3/§5.5/§5.7 не изменяются.

## Consequences

**Положительные:**

- Предметная логика изолирована по доменам: реестр/ACL не смешиваются с winget и гипервизорным слоем.
- Доменные данные становятся декларативными манифестами, а не кодом — появляется основа для идемпотентности (AR-301) и аудита дрейфа.
- `docs/research/` легализован: `GATE_STRUCTURE` закрыт, `STRUC_002` соблюдён.

**Отрицательные / компромиссы:**

- `scripts/` сохраняет исторические имена `Stage<N>_*.ps1`, что сохраняет совместимость §5.6, но оставляет неоднородность «оркестрация vs домен» — она зафиксирована правилом AR-501.
- Дополнительные README.md в каждом каталоге (требование `STRUC_003`).

**Нейтральные:**

- Имена каталогов — lowercase-kebab-case (`STRUC_004`), кроме исторически сложившихся `research1` → снято переносом в `docs/research/`.
- Бинарники и ISO по-прежнему не хранятся в Git (AR-804, ADR-0006).

## Alternatives

| Вариант | Описание | Причина отклонения |
|---|---|---|
| B | Полная перестройка в домен-ориентированный монорепо (`/core`, `/packages`, `/devops`, …) | Ломает §5.6 и исторические имена скриптов; высокий риск для утверждённого контура; требует переписывания README целиком |
| C | Корень не трогать, домены уложить внутрь `scripts/` и `docs/` | Не решает задачу разделения доменов; сохраняет монолитность; противоречит запросу владельца |

## Verification

- `git status` до коммита: перенос зафиксирован как `R` (rename) для 6 файлов.
- Все новые каталоги содержат `README.md` (`STRUC_003`).
- Валидатор `scripts/rules/Test-RepositoryConventions.ps1` — `PASS` (эквивалентная проверка в песочнице).
- §5.1/§5.4/§5.6 README приведены в соответствие фактическому дереву.

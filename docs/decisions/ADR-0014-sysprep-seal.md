## Context

Stage 5 — запечатывание монолита: `sysprep.exe /oobe /generalize /shutdown` с вторым файлом ответов. Это первая и единственная операция проекта, которая (а) необратима и (б) выполняется по схеме `unattend`, где ошибка приводит не к «неудобству», а к нерабочему OOBE и потере одноразового прогона generalize.

Исходные данные:
- `docs/research/step4.md` задаёт состав файла ответов, но содержит дефекты: неверные пространства имён `wcm`/`xsi`, элемент `<HideLocalAccountScreen>`, применимый только к Windows Server (проверено по документации Microsoft), компонент `Microsoft-Windows-MPR`, существование которого не подтверждается справочником unattend, и PowerShell-однострочники, склеивающие несколько операций;
- README §2.3 запрещает менять `CopyProfile=true` — решение принято и пересмотру в рамках проекта не подлежит;
- успешность generalize зависит от состояния AppX: пакет, установленный для пользователя, но не provisioned для всех, валит проверку `SYSPRP AppxSysprep` с `0x80073cf2`;
- в сборках 23H2/24H2 известен дефект CopyProfile: кэши `WebCache`/`INetCache` в профиле-источнике переносятся в `Default User` и ломают оболочку нового пользователя;
- AR-204 относит `sysprep` к деструктивным операциям: запуск — только по отдельному подтверждению;
- AR-206 требует объявлять пути записи; каталог `C:\Windows\System32\Sysprep` в allow-list отсутствовал.

## Decision

1. **Размещение файла № 2 — строго `C:\Windows\System32\Sysprep\unattend.xml`** (`ADR-0005` п.1). Каталог добавлен в allow-list `scripts/common/Guard.psm1` отдельной строкой со ссылкой на этот ADR. Копирование выполняет `scripts/Stage5_Sysprep_Prepare.ps1`; путь вне каталога `Sysprep` для этого файла запрещён.
2. **`CopyProfile=true` сохраняется** (запрет §2.3). Приняты документированные ограничения механизма: настройки, шифруемые ключом пользователя (в первую очередь сопоставления приложений по умолчанию), не переносятся; это не считается дефектом этапа.
3. **Защита от дефекта 23H2/24H2:** перед generalize рекомендуется очистка `WebCache`/`INetCache`/`WebCacheLock.dat` профиля-источника (`-PurgeProfileCaches`). Если очистка невозможна (файлы заняты), отказ фиксируется как `WARN`, а устранение переносится в Stage 6 (`SetupComplete`-подобный сценарий первичной инициализации).
4. **Никакой хирургии AppX в unattend.** Удаление пакетов — прерогатива Stage 4 (`tweaks/appx/AppxRemoval.json`, AR-507). Роль Stage 5 — предпролётная проверка ловушки `0x80073cf2` и её устранение только по объявленным шаблонам (флаг `-FixSysprepValidation`).
5. **Состав файла ответов — только проверяемые схемы:** политики `reg add` (атомарно, каждая в своём `RunSynchronousCommand`), `CopyProfile`, `CEIPEnabled`, блок `OOBE` без `HideLocalAccountScreen`, часовой пояс. Отступления от `docs/research/step4.md` перечислены в шапке шаблона как `S5-DEV-1…S5-DEV-4`.
6. **Запуск Sysprep — только явным флагом** `-ExecuteSysprep` (AR-204); по умолчанию скрипт готовит среду, проверяет предусловия и печатает точную команду для CMD.
7. **Часовой пояс файла № 2** — `Russian Standard Time` (как в исследовании). Контрольная точка `S5-OPEN-1`: при ином фактическом поясе значение меняется одной строкой в шаблоне.

## Consequences

**Положительные:**

- Все дефекты исходного черновика изолированы и документированы, а не воспроизведены в боевом файле.
- Ловушка `0x80073cf2` перехватывается до generalize — сохраняется одноразовый прогон и время восстановления.
- Предпролётный отчёт даёт PASS/FAIL по каждому пункту (AR-307) и пишется в `docs/artifacts/Stage5_preflight.md`.

**Отрицательные / компромиссы:**

- `ResetBase` (Stage 4) и generalize необратимы: восстановление — только повторное развёртывание (`SC_FACTORY_RESET_CAPABLE`).
- Копирование кэшей может не понадобиться, но очистка безвредна; отказ от неё оставляет риск дефекта оболочки.
- Настройки, привязанные к пользователю, не наследуются — часть твиков профиля придётся поддерживать политиками (Stage 6).
- `H-004` (Ohook переживает generalize) остаётся PENDING до фактического прогона: ADR-0004 не отменяется, но проверка откладывается на Stage 6.

**Нейтральные:**

- Номер `-FixSysprepValidation` использует `Remove-AppxPackage -AllUsers` для узкого набора шаблонов; операция идемпотентна.

## Alternatives

| Вариант | Причина отклонения |
|---|---|
| Перенести файл № 2 на носитель F: | `unattend.xml` с `CopyProfile` обязан лежать в каталоге Sysprep; Ventoy-носитель читается только на этапе установки (ADR-0005) |
| Скопировать черновик `step4.md` дословно | Неверные `wcm`/`xsi`, неподтверждённые элементы → отказ разбора файла ответов |
| Оставить элемент `HideLocalAccountScreen` | Применим только к Windows Server; риск отказа разбора и нулевая польза на клиенте |
| Убрать `CopyProfile` | Прямой запрет README §2.3; потеря `H-003`/`SC_FACTORY_RESET_CAPABLE` |
| Удалять AppX в `specialize` | Валидация Sysprep проходит до применения файла ответов — ловушка так не закрывается; AR-507 относит удаление к Stage 4 |
| Запускать Sysprep автоматически | AR-204: деструктивная операция требует отдельного подтверждения |

## Context

Прогон Stage 1 выявил два открытых пункта, требовавших решения владельца (`GATE_PARTITIONING`):

**DEV-1 — точка монтирования ESP.** README §6.2 указывал `F:\EFI`, §7.2 — `C:\EFI`, при этом буква `F:` закреплена за USB-носителем Ventoy (README §5.7, §8). Любой из вариантов «с буквой» создавал конфликт: присвоение ESP буквы `F:` на целевой системе недопустимо (занята носителем), а `C:\EFI` вводит дополнительную точку монтирования системного раздела.

**DEV-2 — единицы измерения.** Схема выражалась в «ГБ» без указания системы: `200 ГБ + 279.7 ГБ = 480 ГБ` сходится только в десятичных единицах (SI, 1 ГБ = 10⁹ байт), тогда как интерфейсы разметки (DiskGenius) и штатные инструменты Windows (`Get-Partition`) оперируют двоичными единицами (1 GiB = 2³⁰ байт). При вводе «279» в GiB-поле инженер получил бы раздел на ~47 GiB больше, чем подразумевала документация, — при необратимой операции (разметка уничтожает данные) это недопустимый класс ошибок.

Дополнительно: исходное значение `~232 GiB` для остатка, упомянутое в переписке при выборе варианта, было **арифметически ошибочным** — корректный остаток ≈ 246.7 GiB (накопитель 480 ГБ = 447.03 GiB).

## Decision

1. **Каноническая единица — байты; пользовательское представление — MiB/GiB** (двоичные, 1024-based). Все документы, схемы и параметры скриптов используют MiB/GiB; байтовые значения задаются для полей ввода инструментов разметки.
2. **Целевая геометрия (rev.2, заменяет ADR-0007 §3 в части размеров и точки монтирования):**

| # | Тип | ФС | Размер | Байты (эталон) | Кластер | Монтирование |
|---|---|---|---|---|---|---|
| 1 | ESP | FAT32 | 260 MiB | 272 629 760 | 4 КБ | **без буквы диска (скрытая)** |
| 2 | MSR | — | 16 MiB | 16 777 216 | — | hidden |
| 3 | Windows | NTFS | 200 GiB | 214 748 364 800 | 4 КБ | `C:\` |
| 4 | Data | NTFS | остаток ≈ **246.7 GiB** | по факту | 64 КБ | `D:\` |

3. **ESP не получает букву диска.** `F:` остаётся за USB-носителем Ventoy; от `C:\EFI` (README §7.2) отказ: дополнительная точка монтирования системного раздела не даёт функциональных преимуществ и усложняет схему. Доступ к ESP при необходимости — через `mountvol`/`diskpart` временно, по процедуре, зафиксированной в `Recovery_Procedure.md` (Stage 5+).
4. **Раздел Data создаётся последним и получает весь остаток** ёмкости (не фиксированное число): это исключает появление нераспределённого пространства и делает схему устойчивой к разбросу фактической ёмкости накопителей класса «480 ГБ» (447–448 GiB).
5. **Верификация использует двоичные единицы:** `Stage1_DiskGenius_Partition.ps1` принимает `-EspSizeMiB`, `-MsrSizeMiB`, `-SystemSizeGiB`, `-DataSizeGiB` и сравнивает фактические размеры в байтах с допуском (MiB). Прежняя логика двойной трактовки SI/GiB удаляется — единицы однозначны.
6. **ADR-0007 ревизуется (rev.2).** Неизменными остаются: GPT, UEFI, выравнивание 1 MiB (`PAT-NEW-6`), состав и порядок разделов, файловые системы и кластеры, ручной способ разметки, запрет exFAT. Изменяются: единицы измерения (п.5) и точка монтирования ESP (п.3).
7. **README и `docs/storage/*` приводятся в соответствие** в том же коммите (AR-0.2: правило и артефакты меняются вместе).

## Consequences

**Положительные:**

- Устранён класс ошибок «ввёл число не в тех единицах» при необратимой операции.
- Схема не содержит «магических» чисел остатка: `D:` всегда = весь остаток.
- Конфликт буквы `F:` снят; ESP по умолчанию скрыта — меньше поверхность изменений на целевой системе.

**Отрицательные / компромиссы:**

- Документы проекта, где значения указаны в SI (README §8, `F_drive_schema`), требуют приведения к GiB при создании Stage 2 (учтено в задачах этапа).
- Расхождение «200 GiB» с прежними «200 ГБ» в переписке и ранних редакциях README: исторические значения помечены как SI-less и заменены (см. ADR-0007 rev.2).

**Нейтральные:**

- Фактический размер `D:` зависит от модели накопителя (447–448 GiB) — допуск верификации 4096 MiB покрывает разброс.

## Alternatives

| Вариант | Причина отклонения |
|---|---|
| Оставить SI (200 ГБ + 279.7 ГБ) | Не соответствует интерфейсу инструмента разметки; требует ручного пересчёта в байты при вводе; порождает ровно ту ошибку, из-за которой поднят DEV-2 |
| Оставить GiB, но с фиксированным `D:` (например, 240 GiB) | Нераспределённый остаток не имеет назначения и усложняет схему без выгоды |
| ESP как `F:\EFI` (README §6.2) | Буква `F:` закреплена за USB-носителем |
| ESP как `C:\EFI` (README §7.2) | Лишняя точка монтирования системного раздела; не требуется для обслуживания |
| ESP с буквой (любой) на целевой системе | Расширяет поверхность изменений; скрытая ESP — состояние по умолчанию у Windows |

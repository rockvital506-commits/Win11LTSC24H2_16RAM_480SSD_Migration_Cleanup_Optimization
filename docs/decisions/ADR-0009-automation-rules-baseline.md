## Context

До генерации кода автоматизации требовалось зафиксировать свод правил, устраняющий три класса рисков:

1. **Технические коллизии кодировок.** Windows PowerShell 5.1 без BOM читает `.ps1` как ANSI/CP1251 (кириллица и синтаксис ломаются), тогда как парсер WinPE `setup.exe` **отклоняет** файл ответов с BOM, а `cmd.exe` и WSH не поддерживают UTF-8. Единое правило «BOM везде» технически неисполнимо (обоснование — `docs/research/step1.md`, `docs/research/step5.md`).
2. **Риск необратимых изменений.** Скрипты проекта работают с реестром, ACL, BCD, разметкой диска и гипервизорным стеком. Неавторизованное удаление/переименование/перемещение файлов и деструктивные операции должны быть исключены процессно.
3. **Управляемость дрейфа.** Целевые решения проекта (NTFS Deny SYSTEM, отключение VBS/HVCI, фиксированный pagefile, `mainMem.useNamedFile=FALSE`) должны воспроизводиться детерминированно при каждом запуске (в т.ч. из «крутящейся» задачи `System_Immunity_Core`).

## Decision

Утверждён свод `docs/rules/AUTOMATION_RULES.md` версии **1.0.0** (AR-101 … AR-906), ключевые положения:

1. **Матрица кодировок по классу файла (AR-101, утверждено отдельно):**
   `.ps1/.psm1/.psd1` — UTF-8 **с BOM**; `.xml` (unattend, ventoy) — UTF-8 **без BOM**; `.bat/.cmd/.vbs/.inf` — ASCII-only без BOM; `.reg` — UTF-16LE; `.md/.json/.yaml` — UTF-8 без BOM, **LF**; остальное — CRLF (AR-102).
2. **Запрет самостоятельного удаления/переименования/перемещения файлов (AR-201/AR-202)** с протоколом `GATE_DELETE`; запрет `git rm`/`git mv`/force-push/перезаписи истории без явного одобрения (AR-203).
3. **Идемпотентность, dry-run и наблюдаемость (AR-301…AR-308):** `-Audit`/`-WhatIf`, бэкап-перед-изменением, единые коды возврата (`0/10/20/30/99`), обязательный verification-блок PASS/FAIL.
4. **Стиль и совместимость (AR-401…AR-409):** Windows PowerShell 5.1, запрет `? :` и `??`, запрет интерактивности и алиасов, шапка по `templates/Script-template.ps1`.
5. **Доменные правила:** `tweaks/` — только декларативные манифесты, без ad-hoc `reg add` (AR-501); `packages/` — winget-first с фиксацией версий и lock-файлом (AR-601…AR-607); `devops/` — WSL2+WHP, `systemd=true`, изоляция кэшей, P+E-политика (AR-701…AR-710).
6. **Процессный контур (AR-901…AR-906):** DoD шага, Pester, обязательный прогон валидатора перед коммитом, ограничения AI-агента (не удалять файлы, не менять Section 1–3, не менять топологию без gate).
7. **Протокол изменения правил (AR-0.2):** только через ADR + одобрение владельца + запись в `RULES_CHANGELOG.md`; waivers — с датой истечения.
8. **Политика сети для скриптов (AR-709):** скрипты не поднимают сеть самостоятельно. Это согласуется с §4.5 README; существующие процедуры этапов 6–7 (кратковременный выход в сеть при активации Ohook, подключение на этапе 7) остаются в силе и выполняются человеком-инженером.

## Consequences

**Положительные:**

- Правила исполняемы: `.editorconfig`, `.gitattributes`, `.gitignore` и валидатор закрывают AR-101…AR-106, AR-207 и STRUC-конвенции машинно.
- Исключён класс ошибок «кириллица в bat» и «BOM в unattend.xml», ломавших установку.
- Зафиксирован безопасный контур: ни агент, ни скрипт не удаляют артефакты автономно.

**Отрицательные / компромиссы:**

- Двойной стандарт кодировок требует дисциплины: валидатор обязателен (AR-106, AR-903).
- Часть правил проверяется эвристикой (ограничения `LIM-2`, `LIM-3` в `RULES_CHANGELOG.md`) до подключения PSScriptAnalyzer в версии 1.1.0.

**Нейтральные:**

- README §1–§3 не изменяются; свод правил дополняет их, не отменяя.

## Alternatives

| Вариант | Описание | Причина отклонения |
|---|---|---|
| Единая политика «UTF-8 с BOM для всего» | Простое правило | Технически неисполнимо: `setup.exe` отклоняет BOM в unattend.xml; `cmd.exe` ломает первую строку |
| Единая политика «UTF-8 без BOM для всего» | Простое правило | PowerShell 5.1 читает файлы как CP1251 → кириллица и парсинг ломаются |
| Только документарные правила без валидатора | Минимум усилий | Нарушения не обнаруживаются автоматически; противоречит §3.1 «Zero Tolerance» и AR-903 |

# ADR-0006 — F:\ как производный репозиторий (артефакты вне Git)

|---|---|

| `DATE` | 2026-10-01 |

| `RELATED` | README §5.7, §8, §4.1 (`GATE_FDRIVE_MODIFICATION`); AR-202, AR-204, AR-804, AR-901; PAT-20; `packages/hashes/PACKAGES_SHA256.txt`; `docs/storage/F_drive_schema.md` |

## Контекст

ISO-образы, установщики и portable-инструменты превышают допустимый размер файла Git (лимит GitHub 100 МБ;
внутренний предел проекта — 50 МБ, AR-804). Станция работает офлайн: источником артефактов должен быть
физический носитель, а не сеть. При этом `F:\` — не только хранилище: с него выполняется установка
(Ventoy), поэтому его структура должна быть воспроизводимой и проверяемой.

## Решение

1. **F:\ — производный репозиторий артефактов**: бинарники, ISO и portable-инструменты хранятся на носителе
   вне Git (AR-804). В репозитории — только описания, пути и контрольные суммы (PAT-20).
2. **Структура носителя фиксирована** (README §5.7, §8): раздел 1 — Ventoy (FAT32, 1 ГБ), раздел 2 — ISO
   (exFAT, кластер 512), раздел 3 — вспомогательный (NTFS, кластер 16 КБ: `\TOOLS\`, `\WSL2\`, `\VM\`).
3. **Целостность — через хэши**: SHA256 каждой поставки фиксируется в `packages/hashes/PACKAGES_SHA256.txt`;
   проверка — перед использованием (принцип hash-first).
4. **Любое изменение F:\ — только по решению владельца** и через `GATE_FDRIVE_MODIFICATION` (AR-202):
   скрипты не пишут на носитель без явного подтверждения. Пример реализации — `Stage2_Ventoy_Template_Setup.ps1`
   (запись только с `-DeployToMedia -AcknowledgeFDriveModification`).
5. **F:\ не является источником истины** для конфигурации: истина — репозиторий (манифесты, шаблоны, ADR).
   Носитель можно пересобрать по документации; обратное неверно.
6. **Удаление артефактов с носителя автономно запрещено** (AR-201): замена файла — только с новым хэшем
   и записью в отчёте этапа.

## Альтернативы

| Вариант | Оценка |
|---|---|
| A. F:\ как производный репозиторий | **Принят.** Офлайн-first, лимиты Git не нарушаются, структура воспроизводима |
| B. Git LFS | Отклонён: требует сети, платных квот и не решает офлайн-установку |
| C. Хранить артефакты в Git | Отклонён: лимит 100 МБ/файл, раздувание клона, AR-804 |
| D. Облачное хранилище | Отклонён: станция офлайн (§1.3), проверка целостности вне контроля владельца |

## Последствия

- Описания артефактов дублируются в двух местах: `docs/storage/F_drive_schema.md` (структура) и
  `packages/hashes/PACKAGES_SHA256.txt` (хэши) — синхронность обеспечивается проверками этапов 2 и 7.
- Пересборка носителя возможна только вручную (владелец), поэтому структура разделов зафиксирована в ADR-0007/0011.

## Верификация

| ID | Проверка | Ожидание |
|---|---|---|
| `V1` | Структура разделов F: | соответствует README §8.3–8.5 |
| `V2` | Хэши поставок | заполнены и совпадают (PAT-20) |
| `V3` | Запись на носитель | только с подтверждением (`GATE_FDRIVE_MODIFICATION`) |
| `V4` | Бинарники в Git | отсутствуют (`git ls-files`, AR-804) |
